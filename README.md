# HH Clicker

Локальная панель автоматизации HH.ru. Приложение может отправлять реальные
отклики: перед включением профиля проверяйте резюме, фильтры и письмо.

## Структура

```text
client/       React + TypeScript + Vite
  src/        исходники интерфейса
  static/     ресурсы и прежний интерфейс
    dist/     собранный React
server/
  app/        FastAPI и логика бота
  tests/      Python-тесты
  scripts/    обслуживание и миграции
  web_app.py  точка запуска
data/         SQLite, диагностические логи и runtime-lock (не коммитить)
.env          локальные секреты (не коммитить)
```

## Docker Desktop

Все команды выполнять из корня проекта. Запуск восстанавливает активные профили.

```bash
# Запуск / обновление
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build hh-bot

# Остановка без удаления данных
docker compose -f docker-compose.yml -f docker-compose.local.yml stop hh-bot

# Логи
docker compose -f docker-compose.yml -f docker-compose.local.yml logs -f --tail=100 hh-bot
```

Панель: <http://127.0.0.1:8000/>. Используйте локальный Compose override:
он ограничивает доступ этим компьютером и отключает необязательный proxy sidecar.
Ключ панели — `HH_BOT_API_KEY` в `.env`; не помещайте его в исходники клиента.

## Разработка клиента

```bash
npm --prefix client ci
npm --prefix client run dev
npm --prefix client run build
```

Dev-интерфейс: <http://localhost:5173/>. API и WebSocket проксируются на порт 8000.
Сборка пишется в `client/static/dist/`; сервер отдаёт её на `/` (маршруты — через hash: `/#/settings`).

## Разработка сервера

Используйте отдельное виртуальное окружение. Из корня проекта:

```bash
python -m pip install -r server/requirements.txt -r server/requirements-dev.txt
python server/web_app.py
python -m pytest -c server/pytest.ini server/tests
```

При запуске без Docker переменные из `.env` должны быть заданы в окружении.
Не запускайте вторую копию сервера с теми же рабочими данными одновременно.
Не публикуйте `.env`, содержимое `data/` и логи с токенами.

## База данных

Постоянные данные хранятся в `data/hh-clicker.sqlite3`: аккаунты, настройки,
фильтры резюме, токены, отклики, тестовые вакансии, переписки, OTP-state и события.
SQLite работает в WAL-режиме с транзакциями и внешними ключами. Таблицы содержат
отдельные записи, а не один общий JSON; вложенные HH-поля сохраняются как JSON
внутри записи. Это позволяет не терять неизвестные поля при обновлениях API.

При первом запуске старые JSON/JSONL импортируются одной транзакцией. После
этого они не читаются и не обновляются. Ошибка импорта останавливает запуск;
не удаляйте БД для «повторной миграции»: можно потерять новые отклики и токены.
Старые резервные снимки импортируются отдельно в `legacy_artifacts`, не
добавляются в актуальную историю и могут содержать секреты.

```bash
# Проверка количества записей без вывода токенов
python server/scripts/database_admin.py status

# Согласованная копия, в том числе при работающем сервере
python server/scripts/database_admin.py backup --output backups/manual.sqlite3
```

Для миграции с проверкой совпадения исходных JSON используйте `migrate` при
остановленном сервере и до архивирования старых файлов. В панели экспорт и
восстановление работают с БД; JSON остаётся только форматом обмена.

Бэкап через `backup_data.py --apply` использует SQLite backup API (учитывает WAL).
Восстановление архива требует остановленного сервера. Не копируйте один файл
работающей БД вручную: свежие записи могут находиться в `-wal`.
Доступ к БД ограничен владельцем файла (0600), но содержимое не зашифровано.
Для отката после миграции нужны согласованные старые данные **и** старый код;
после возобновления откликов старый JSON-бэкап уже устарел.
